# MySMS clients

The client workspace for MySMS: the web app (W), the platform console (C), the phone apps for students, parents and teachers (S/P/T) and the tablet learning app (B). All are built on one generated SDK and shared packages. The architecture is specified in [`../ui/05-frontend-architecture.md`](../ui/05-frontend-architecture.md); the screens in [`../ui/02-navigation-and-screens.md`](../ui/02-navigation-and-screens.md).

## Build and run

Prerequisites, `pnpm install` / `pnpm verify`, single-package commands and the dev servers: [`../BUILD-AND-RUN.md`](../BUILD-AND-RUN.md) §1, §3.2 and §4.3. Phone and tablet apps (Expo, EAS builds): [`../DEPLOYMENT.md` §9](../DEPLOYMENT.md#9-phone-and-tablet-apps); build-time variables: [`../DEPLOYMENT.md` §4.3–§4.4](../DEPLOYMENT.md#4-configuration-reference).

The SDK is generated by [OpenAPI Generator](https://github.com/OpenAPITools/openapi-generator) (`typescript-fetch`, version pinned in `packages/sdk/openapitools.json`), a Java program, so a JDK must be on `PATH`. The generator jar is downloaded from Maven Central on first use; set `OPENAPI_GENERATOR_JAR` to use a local copy.

The apps always talk to a real backend: run the monolith and sign in with the tenant code and administrator created by the bootstrap variables. `MYSMS_API_PROXY` (web) or `EXPO_PUBLIC_API_BASE_URL` (Expo, default `http://localhost:8080`) points elsewhere. **Mocking is done only in tests**: the fake backend in `packages/fixtures` is imported by `*.test.*` files only, and ESLint fails the build if shipping code imports it or calls `vi.mock`.

## Rules

These are enforced by ESLint, the type checker and the tests:

- Apps and kits call the API only through `@mysms/core` hooks, never `@mysms/sdk` directly. `ui-*` packages import only `tokens` and `i18n`.
- No literal copy in components. Every string comes from the catalogue, with keys `module.screen.element`. Enum values are shown through catalogue labels, never raw.
- Permission codes, the screen/route table and the operation-owning modules are generated from the contracts, so a typo is a compile error.
- `core` keeps 90 % line coverage. Every web component passes an axe check.
- The initial JavaScript of each web app stays within 300 KB gzip; the build fails otherwise.
- One React version for the whole workspace (pinned by a pnpm override), so React Native bundles never contain two copies.
- Shared code must not use `URL.pathname` or `URLSearchParams.get`/`has`, which React Native does not implement. Use `pathOf`, `searchOf` and `parseQuery` from `core`.
