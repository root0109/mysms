# MySMS clients

The client workspace for MySMS: the web app (W), the platform console (C), the phone apps for students, parents and teachers (S/P/T) and the tablet learning app (B). All are built on one generated SDK and shared packages. The architecture is specified in [`../ui/05-frontend-architecture.md`](../ui/05-frontend-architecture.md); the screens in [`../ui/02-navigation-and-screens.md`](../ui/02-navigation-and-screens.md).

## Requirements

Node 22.12 or later, pnpm 10 (`corepack enable`) and Java 17 or later on `PATH`: the SDK is generated by [OpenAPI Generator](https://github.com/OpenAPITools/openapi-generator) (`typescript-fetch`, version pinned in `packages/sdk/openapitools.json`), which is a Java program. The generator jar is downloaded from Maven Central on first use; set `OPENAPI_GENERATOR_JAR` to use a local copy.

## Commands

```bash
pnpm install
pnpm verify          # generate → typecheck → lint → test → build, for every package and app
pnpm --filter @mysms/web dev               # W on http://localhost:5173 (proxies /v1 to the monolith on :8080)
pnpm --filter @mysms/platform-console dev  # C on http://localhost:5174
pnpm --filter @mysms/mobile start          # Expo, student app; start:parent / start:teacher for the other targets
pnpm --filter @mysms/tablet start          # Expo, tablet app
```

The apps always talk to a real backend: run the monolith (`../DEPLOYMENT.md` §5.2) and sign in with the tenant code and administrator created by the bootstrap variables. `MYSMS_API_PROXY` (web) or `EXPO_PUBLIC_API_BASE_URL` (Expo, default `http://localhost:8080`) points elsewhere. **Mocking is done only in tests**: the fake backend in `packages/fixtures` is imported by `*.test.*` files only, and ESLint fails the build if shipping code imports it or calls `vi.mock`.

## Rules

These are enforced by ESLint, the type checker and the tests:

- Apps and kits call the API only through `@mysms/core` hooks, never `@mysms/sdk` directly. `ui-*` packages import only `tokens` and `i18n`.
- No literal copy in components. Every string comes from the catalogue, with keys `module.screen.element`. Enum values are shown through catalogue labels, never raw.
- Permission codes, the screen/route table and the operation-owning modules are generated from the contracts, so a typo is a compile error.
- `core` keeps 90 % line coverage (currently 100 %). Every web component passes an axe check.
- The initial JavaScript of each web app stays within 300 KB gzip; the build fails otherwise.
- One React version for the whole workspace (pinned by a pnpm override), so React Native bundles never contain two copies.
- Shared code must not use `URL.pathname` or `URLSearchParams.get`/`has`, which React Native does not implement. Use `pathOf`, `searchOf` and `parseQuery` from `core`.

## Verified

- `pnpm verify` is green.
- Both Expo apps bundle with Metro: mobile for Android, tablet for iOS. Each bundle contains one copy of React.
- The console was driven in a real browser: sign in, edit a country under If-Match, cancel a job at its owning module.
- The web app was driven in a real browser against the real monolith on PostgreSQL: sign in as the bootstrap administrator, ADM-11 Records — create an institution, required-field errors, create a student category in it, a duplicate code answered 409 and shown, edit under If-Match, delete.
