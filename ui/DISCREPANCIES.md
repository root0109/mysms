# Spec and contract discrepancies

Where the spec in this folder and the contract (`../api`) disagreed, what was built (ui/06 §6).

| Screen / flow | What differed | What was built |
|---|---|---|
| F2 step 1, ADMN-01 | ui/03 lists `admission.StartAdmission` before `admission.OpenApplications`; the cycle's states (`draft → confirmed → open → admission → closed`, cancel allowed up to `open`, close from `open` or `admission`) put the admission stage after the open one. | Confirm → OpenApplications (takes applications) → StartAdmission (decides, takes no new ones) → Close (api/state-machines.md). |
| F2 step 3, ADMN-03 | ui/03 places `admission.ConfirmApplication` after approval; operations.md defines it as "office confirms the application is complete". | Submitted (or on hold) → ConfirmApplication → ApproveApplication → ConfirmAdmission (fee paid or waived) → EnrollApplicant. |
| ADMN-05 | The inventory marks the form "W (public)", but `admission.CreateApplication` and `SubmitApplication` need a bearer token (no public operation in the contract) and `applicationNumber` is required on create. | The form needs a signed-in applicant account; the client proposes a provisional application number (`W-<yyyymmdd>-<6 characters>`). Uploads are not part of the form yet. |
| ADMN-04 | "Section/batch" pickers: a class section has no name in the contract (its name is its grade level and section). | The wizard takes the class section or batch id, prefilled from the application. |
| HR-08 | The inventory offers a payslip PDF download; no served operation renders a payslip (`document_file_id` stays empty). The contract has one read permission (`payroll.payslip.read`) for every payslip. | The payslip is shown on screen with its lines and totals, with a note that the PDF is not available. The server keeps payslips owner-only: a caller who is not a payroll officer (`payroll.payslip.generate_payslips`) for the payslip's institution reads only the payslips of their own staff records, kept from hr's staff events (api/state-machines.md "payroll.Payslip"). |
| HR-07, F7.2 | ui/03 reads "review payslips (deductions from leave)" and the operation is "Generate payslips from staff salaries, leave and attendance"; the request carries no leave or attendance input and payroll does not read hr's leave yet. | Payslips pay the staff salary components for the days of the month each salary is in force; pay percentage stays 100 and leave days and leave deduction 0. A period lies within one calendar month. |
| HR-05 | "Templates with their components (add, edit, remove, order)": a template component has no order of its own in the contract. | Components are listed in the order they were added; payslips list lines by the pay components' own order. |
| LMS-49 | The contract's `lms.ReceiveToolOutcome` also names LTI Advantage scores (JSON + JWT) | Served LTI 1.1 Basic Outcomes only (XML + OAuth 1.0a body hash); an AGS JSON body answers 422. LTI 1.3/AGS waits on its platform dependency (ui/02 §3 LMS-49 note). |
